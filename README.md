# EntiWeave

A pipeline for generating, evaluating, and training on graph-grounded QA datasets for deep search agent.

---

## 1. Setup

### Python Environment

This project uses [`uv`](https://docs.astral.sh/uv/) for Python environment and dependency management. It requires Python 3.12 or newer.

Install `uv` if it is not already available:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Create the virtual environment and install dependencies from `uv.lock`:

```bash
uv venv --python 3.12
uv sync
```

Activate the environment when you want to run commands directly:

```bash
source .venv/bin/activate
```

You can also skip activation and prefix commands with `uv run`, as shown in the examples below.

### Environment Variables

Run the setup script to populate `.env` in the project root:

```bash
bash scripts/setup/load_env.sh
```

The `.env` file must contain the following variables:

| Variable | Description |
|---|---|
| `TOOLS_API_KEY` | API key for authenticating requests to the tool server |
| `MONGODB_URL` | MongoDB connection string — used to store generated QA pairs and graphs |
| `OPENAI_API_KEY` | OpenAI-compatible API key for the generation model |
| `JINA_API_KEY` | Jina AI API key (required if using Jina as searcher or retriever) |
| `SERPER_API_KEY` | Serper API key (required if using Serper as searcher) |

### Dataset

Decrypt the bundled encrypted datasets and download the EntiWeave train splits from HuggingFace:

```bash
bash scripts/setup/prepare_dataset.sh
```

This will:
1. Decrypt files from `data/encrypted/` back into `data/dataset/` and `data/eval/`
2. Download `train` and `train_sft` splits from HuggingFace dataset, saving them as `data/dataset/entiweave_train.json` and `data/dataset/entiweave_train_sft.json`

## 2. Tool Server

The tool server is a FastAPI service that provides web search and page retrieval to agents.

### Running

```bash
uv run tool_server/main.py --port 8001 --searcher-type ddg --retriever-type custom
```

| Argument | Options | Default | Description |
|---|---|---|---|
| `--port` | any port | `8001` | Port to listen on |
| `--searcher-type` | `ddg`, `jina`, `serper`, `local` | `local` | Search provider |
| `--retriever-type` | `custom`, `jina`, `local` | `local` | Web page retriever |
| `--local-search-url` | URL | `http://localhost:8080` | URL for the `local` search provider |

### Searchers

- **`serper`** — Serper API; reliable and fast. Requires `SERPER_API_KEY`.
- **`jina`** — Jina AI search API. Requires `JINA_API_KEY`.
- **`ddg`** — DuckDuckGo. No API key needed, but **use sparingly** — DuckDuckGo rate-limits and blocks automated usage. Not suitable for large-scale generation runs.
- **`local`** — Forwards to a separate local search server at `--local-search-url`.

### API

All endpoints require an `X-API-Key` header matching `TOOLS_API_KEY`.

```
GET /search?q=<query>&num=<n>     # Run a web search
GET /click?url=<url>              # Fetch and parse a web page
```

## 3. QA Generation

QA pairs are generated by building a compositional knowledge graph from a seed entity, expanding it via web search, and converting it into multi-hop questions.

**All generated data is saved to MongoDB** under the `cokg` database (collections: `gen_graphs`, `seeds`, `qa_pairs`).

Make sure the tool server is running before starting generation.

### Running

```bash
NUM=10 BROWSER_URL=http://localhost:8001 ./scripts/generation/gen_qa.sh
```

### Key Environment Variables

| Variable | Default | Description |
|---|---|---|
| `NUM` | — | Number of QA pairs to generate |
| `BROWSER_URL` | — | Tool server URL |
| `MODEL` | — | Generation model name (e.g. `GLM-4.7`) |
| `BASE_URL` | — | LLM API base URL |
| `SAMPLER_TYPE` | — | API type: `glm`, `openai`, `deepseek`, etc. |
| `THINK` | `false` | Enable extended thinking for compatible models |
| `TOPIC` | — | Optional seed topic |
| `CATEGORY` | — | Optional seed category |
| `RUN_ID` | — | Resume a previous run by its ID |
| `MAX_COMPLEXITY` | `20` | Max entities per knowledge graph |
| `MAX_SEARCH_STEPS` | `2` | Max web search steps per entity |

### Resuming a Run

```bash
RUN_ID=<existing_run_id> NUM=50 ./scripts/generation/gen_qa.sh
```

## 4. Trajectory Generation

Trajectories are agent rollouts over QA pairs from `data/dataset/` or `data/eval/`, recording each search/retrieval step taken to reach an answer.

### Running

```bash
NUM=100 DATASET=deepdive OUTPUT_PATH=output/trajectory ./scripts/generation/gen_trajectory.sh
```

Results are written to `output/trajectory/<run_id>/result.jsonl` along with per-sample trajectory files.

### Key Environment Variables

| Variable | Default | Description |
|---|---|---|
| `NUM` | — | Number of samples to run |
| `DATASET` | — | Dataset name (resolves to `data/dataset/<name>.jsonl`) |
| `DATA_PATH` | — | Direct path to a JSONL file (overrides `DATASET`) |
| `OUTPUT_PATH` | — | Output directory |
| `AGENT_TYPE` | `react` | Agent type: `react` or `resumact` |
| `SEARCH_MODEL` | — | Model name for the search agent |
| `SEARCH_BASE_URL` | — | LLM API base URL |
| `SEARCH_TYPE` | — | API type: `glm`, `openai`, `ollama`, etc. |
| `BROWSER_BASE_URL` | — | Tool server URL |
| `CONCURRENCY` | `8` | Parallel agent workers |
| `MAX_STEPS` | `30` | Max actions per trajectory |
| `SKIP_JUDGE` | `true` | Skip answer correctness evaluation |

### Available Datasets

**Training**: `deepdive`, `webexplorer`, `webshaper`, `webwalker`

**Evaluation**: `browsecomp`, `browsecomp_plus`, `browsecomp_zh`, `entiweave_hard`, `frames`, `gaia`, `hle`, `xbench`

## 5. SFT Training (Swift)

Supervised fine-tuning uses the [SWIFT](https://github.com/modelscope/swift) framework with DeepSpeed ZeRO-3 and Flash Attention.

### Prerequisites

Install SWIFT and ensure your dataset is prepared (`data/dataset/entiweave_train_sft.json`).

### Running

Edit the dataset path in `scripts/training/train_swift_sft.sh`, then run:

```bash
bash scripts/training/train_swift_sft.sh
```

### Default Configuration

| Parameter | Value |
|---|---|
| Model | `ZhipuAI/GLM-4.7-Flash` |
| Training type | Full fine-tuning |
| GPUs | 8 |
| Precision | bfloat16 |
| Epochs | 3 |
| Learning rate | 1e-5 |
| Max context length | 128,000 tokens |
| Distributed backend | DeepSpeed ZeRO-3 |
| Attention | Flash Attention 2 |
| Sequence parallelism | 8-way |

Set `CUDA_VISIBLE_DEVICES`, `HF_HOME`, `WANDB_API_KEY`, and `--dataset` in the script before running.


## Serper-compatible endpoints

Set `SERPER_BASE_URL` to a compatible API base (without `/search`) and
`SERPER_API_KEY` to that provider's key. The default remains
`https://google.serper.dev`; trailing slashes are removed before adding the
search route. Other Serper routes use the same base where present.
Support any Serper.dev-compatible endpoint (like litescrape.com, serpbase.dev, serpensapi.org, and others).
